# G4 to G6

## G4 · Delegation concierge (about 4 weeks)

Done when a holder can state what they care about and see how DReps line up with it, with reasons, and the SDK offers vote delegation as an explicit choice.

```text
Session G4.1, repo adasouls-governance: preferences and DRep data.
A small JSON schema for what a holder cares about (for example treasury discipline, developer funding, decentralisation, constitutional strictness), and an ingester for every DRep's votes and rationales from Koios. Store them like G1.1 stores actions.
```

```text
Session G4.2: alignment.
Transparent rules that score how a DRep's votes line up with a preference profile, per action category, plus model-written summaries of the DRep's rationales that cite them. Every score shows its reasons; no hidden weights. Never redelegate anyone automatically.
```

```text
Session G4.3, repo adasouls-sdk-typescript: vote delegation in onboarding.
The default stays always-abstain. The developer can choose the AdaSouls DRep (shown with a link to its conflict of interest policy) or any DRep id, explicitly. An agent may redelegate its own account's vote only to DReps in an allowlist its owner approved. Tests and README.
```

## G5 · Treasury milestone verifier (about 4 weeks)

Done when each treasury-funded project has a public, signed milestone status with its evidence.

```text
Session G5.1, repo adasouls-governance: enacted treasury withdrawals.
Ingest enacted treasury withdrawals and their documents (CIP-108). Extract the milestones each project promised, with model help, citing the exact passages; mark anything unclear as unknown.
```

```text
Session G5.2: evidence.
Collectors for public evidence per milestone: GitHub activity (commits, releases, issues), linked demos, on-chain activity. A status per milestone (delivered, partly, not yet, unknown) with citations.
```

```text
Session G5.3: attestations.
Sign each status as ALMA evidence with the analysis key (alma-core issuer-signature format) and publish it on the G1.5 site. Optional: CIP-0170 attestations.
```

## G6 · Governance evidence in ALMA (about 3 weeks)

Done when an ALMA identity bound to a DRep id or a pool id can show verified governance activity.

```text
Session G6.1, repo alma (packages/alma-core): governance evidence types.
Evidence for a DRep registration and its updates, votes with their rationale anchors, delegations received over time, and stake pool votes, each with the chain references a verifier needs. Spec text in spec/. Add a changeset.
```

```text
Session G6.2, repo alma-verifier: read and check governance evidence from chain for an identity bound to a DRep id or a pool id, and include it in the report.
```

```text
Session G6.3, repo adasouls-sdk-typescript: expose an agent's governance evidence, with docs that explain it to developers.
```
